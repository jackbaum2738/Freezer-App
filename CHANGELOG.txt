FREEZR CHANGELOG
================

Versioning: x.0.0 = major (new features) | 1.x.0 = minor (small additions/changes, batched) | 1.0.x = patch (tiny fixes/tweaks)


10.5.1 -- 2026-08-30
--------------------
- Fixed the colour swatch, name, and delete button in Categories/Freezers settings rows not lining up vertically -- a leftover CSS rule from the Backup feature was silently overriding their height/padding. Rows are also a bit more compact now as a result.
- The "New category name"/"New freezer name" fields now match the "Add" button's height exactly -- the button previously had no vertical padding at all, making it visibly shorter. Same fix applied to the "Your name" field in Settings, which shares the same styling.

10.5.0 -- 2026-08-30
--------------------
- Fixed batch review not pulling in remembered/looked-up names for barcodes it hadn't seen before -- it only checked names already learned locally, unlike single-item scanning, which also does a live product lookup for a brand-new barcode. Batch now does the same lookup per row, filling in name, guessed category, and a best-effort weight guess when it succeeds.
- Batch review rows now also ask for Freezer and Weight, matching the single-item "Confirm item" screen exactly (same fields, same layout, same look) -- previously batch only asked for name and category, silently defaulting weight and freezer for every item in the batch.

10.4.0 -- 2026-08-30
--------------------
- Reworked Inventory and History rows to a clearer 3-line layout: name on its own line; category, weight, quantity, and (with 2+ freezers) which freezer it's in all together on the middle line; the date on its own line at the bottom. History keeps its "Frozen X" duration and "Removed by" attribution, now on their own two lines rather than crammed into one.
- Weight/quantity now shows on Inventory rows for the first time -- it previously only appeared in the item detail popup, History, and the Shopping List.
- Items using the new Count unit now display as "8 count" (previously a bare "8") wherever their weight is shown.

10.3.1 -- 2026-08-30
--------------------
- Renamed the Sort pill's "Alphabetical" option to "Name" on the Inventory list, History, and Shopping List.

10.3.0 -- 2026-08-30
--------------------
- Added a "Count" unit option to the weight/volume picker, for items that are just a plain number with no unit at all (e.g. a pack of 8 sausages). Unlike g/kg/ml/l/oz/lb it doesn't append a unit suffix anywhere the weight is shown -- it just displays the bare number. Unlike Small/Large container, it keeps the amount field so you can actually type the count.

10.2.0 -- 2026-08-30
--------------------
- Added a Sort pill (matching the Category pill's style) to the Freezr inventory list, History, and Shopping List. Tapping it flips directly between "Date" (newest first) and "Alphabetical" -- no picker sheet, since there are only two options. Each of the three lists remembers its own choice independently, saved per-device.
- The inventory list's default order changed from oldest-added-first to newest-added-first, to match Date mode's "newest first" meaning consistently across all three lists. This is purely visual -- removing/using up stock still always takes the oldest physical unit first (FIFO), regardless of what's sorted to the top of the list.

10.1.3 -- 2026-08-30
--------------------
- Fixed the weight field on Android only being tappable near its right edge. It was an <input type="number">, and Android Chrome reserves part of that input's box for its native increment/decrement control even though it's not visibly drawn there with our styling -- switched it to a plain text input with inputmode="decimal" (still brings up the numeric keyboard, still parsed the same way) so the whole box is tappable, like it already was on iOS.

10.1.2 -- 2026-08-30
--------------------
- Fixed the app getting visually stuck zoomed-in/too-wide on iPhone after typing into any text field (reported on an iPhone 16 Pro Max). Every text input in the app had a font-size under 16px, which is the exact threshold that makes iOS Safari auto-zoom the page when a field is focused -- on a PWA in standalone mode that zoom sometimes doesn't reset afterwards, leaving the whole app shifted and cut off on the right edge. Bumped every input/number field to 16px so the zoom never triggers. Also added a defensive overflow-x:hidden on the page as a safety net against this class of bug in general.

10.1.1 -- 2026-08-30
--------------------
- Fixed the remove (X) button on shopping list rows: it was sitting right next to the item name instead of pinned to the row's right edge, because the text wrapper next to it was missing a CSS rule to make it fill the available space. Also made the button vertically centered on the row and slightly bigger, since it was riding high near the top instead.

10.1.0 -- 2026-08-30
--------------------
- Renamed "Export" to "Backup" and moved it from the Freezr screen's icon row into a new Backup section in Settings, which now shows when the last backup was taken and who by (shared across everyone in the Freezr, not per-device).
- Added Restore: pick a previously downloaded backup file and it's checked for validity, then a confirmation screen shows when it was taken and by whom before replacing every item, category, freezer, and history entry in the Freezr with the backup's contents. No Undo -- restoring replaces everyone's data.
- Backup files now save as .freezrbackup instead of .json (still the same format underneath) so they don't invite casual editing in a text editor, and a corrupted or hand-edited file is now rejected with a clear error instead of silently breaking the restore.
- The backup file also now includes the shopping list, which the old export was missing.

10.0.0 -- 2026-08-29
--------------------
- Added a Shopping List: a new third tab (🛒 List, between Freezr and Settings) with a tick-box list, searchable and filterable by category using the exact same pill/sheet component as the inventory list. A badge on the tab icon shows how many items are still to buy.
- Items are added to the list automatically the moment the last unit of something leaves the freezer (scan-to-remove, "Remove from Freezr", or a quantity step-down to zero) -- no duplicates if it's already sitting there unbought, matched by barcode or by name for barcode-less manual items. Undoing that removal un-adds it again too. Scanning something back in silently clears it off the list by barcode -- no extra toast either way, since the removal/scan already has its own.
- Weight shows on each row when known. When 2+ freezers exist, each row also shows which freezer it was last kept in, on its own line.
- Anything can be added by hand too, via a "+" button next to the search box -- same manual-entry pattern as the Add screen, with a guessed category.
- Tick items off as you shop -- they grey out, get struck through, and sink into a "Got it" group so what's left stays at the top. A button pinned above the filters ("Add to Freezr") restocks everything ticked in one tap and clears them off the list. With one freezer it's instant; with two or more it opens a quick review defaulting each item to the freezer it was last kept in, tap any one to reassign before confirming.

9.0.2 -- 2026-08-29
--------------------
- Deleting a Freezr now shows a "Freezr deleted" confirmation before switching you anywhere -- previously it went straight from typing the confirm code to the next screen with no acknowledgment the delete actually happened. Dismiss it with the X, tapping outside it, or Continue -- any of those then switches you to another saved Freezr, or the join/create screen if you have nothing else saved.

9.0.1 -- 2026-08-29
--------------------
- Fixed Freezr deletion always dropping you on the join/create screen, even when another Freezr was already saved on the device. It now switches straight to the most recently saved one instead -- for both the device that deleted it and any other device that discovers the deletion (after acknowledging the "no longer exists" notice). Join/create is now only shown when there's genuinely nothing else saved.

9.0.0 -- 2026-08-29
--------------------
- Added the ability to delete a Freezr, from a red button at the bottom of Settings. Double confirmation: the button opens a warning modal, and Delete stays disabled until you type the Freezr's own code to confirm. No Undo -- it's permanent for everyone in it.
- The app now automatically refreshes when reopened after being backgrounded for a while (previously it only picked up changes -- new code or items added/removed by other devices -- after a manual pull-to-refresh). This is also what delivers the "this Freezr no longer exists" notice to other devices once one has been deleted -- they land on the join/create screen after acknowledging it.
- Fixed a listener leak: switching or reconnecting to a Freezr now properly detaches the previous one's Firestore listener instead of leaving it running in the background.
- The "Your name" Save button in Settings is now filled cyan, matching "Scan items" on the Add screen.

8.1.0 -- 2026-08-29
--------------------
- Changed the manual-entry field on the Add screen from a barcode number to the item's name -- nobody realistically has a barcode memorised to type in. Typing a name and tapping Add opens the same "Confirm item" modal used for scans, pre-filled with that name, with the barcode saved as blank. Since there's no barcode, the name/category/weight aren't saved to the "remembers per barcode" list -- there's nothing to remember them against.
- Removed the manual-entry field from Remove mode entirely -- removing an item without a barcode is done by searching for it in the list and using the remove button there.

8.0.0 -- 2026-08-29
--------------------
- Added a Freezr switcher: Settings now has a "Switch" button that opens a list of every Freezr ever joined or created on this device -- tap one to switch instantly, no need to re-enter its code (e.g. swapping between a uni freezer and a home freezer over a weekend). The active Freezr is checkmarked; others have a remove (✕) button that forgets them from this device only (soft-delete with Undo -- the Freezr itself and its data are untouched).
- A "Join or create another Freezr" row in the switcher reuses the existing onboarding screens, now with a close button since it's optional once you already have a working Freezr.
- Creating a Freezr now asks for a name first (e.g. "Home Freezer", "Uni Freezer") -- shown throughout Settings, the switcher, and the code-reveal screen so multiple Freezrs are easy to tell apart.

7.0.0 -- 2026-08-29
--------------------
- Added an install gate: opening Freezr in a regular browser tab (not installed to the home screen) now shows a full-screen, unskippable screen with install instructions instead of the app itself -- platform-specific steps for iOS (Share -> Add to Home Screen) and Android (Chrome's ⋮ menu, or a one-tap native Install button when the browser offers one), and a simple "open this on your phone" message on desktop. Detects install state via `display-mode: standalone` / `navigator.standalone`. Existing installed users are unaffected.

6.0.0 -- 2026-08-29
--------------------
- Added Freezr households: separate households now keep entirely separate data instead of everyone sharing one freezer. A mandatory first-run screen (before the name prompt) offers "Join a Freezr" (enter a code) or "Create a Freezr" (generates a memorable two-word code like FROSTY-OTTER, seeds default categories/one freezer, shows the code to share).
- Each Freezr now lives in its own Firestore document (`freezrs/{code}`) instead of the old single shared `freezer/inventory` document.
- New "Freezr" block at the top of Settings shows the household's code and a Share button (uses the OS share sheet, or copies a WhatsApp-friendly invite message with the code + install link).
- Renamed the default "Bread & Bakery" category to "Bakery".

5.0.0 -- 2026-08-28
--------------------
- Added a Historical log: every unit that leaves the freezer (scan-to-remove, "Remove from Freezr", or stepping quantity down in the item popup) is now logged separately from the live inventory, with a snapshot of its name/category/weight/freezer, when it was removed, how long it had been frozen, and who removed it.
- New 🕘 button next to the existing category-browse and backup buttons opens the History view -- same search box and Category/Freezer filter pills as the main list.
- Each history row has a re-add (↺) button that restocks its full quantity back into the freezer in one tap, and a remove (✕) button that deletes just that log entry (soft-delete with Undo, same pattern as everywhere else).
- Undoing an original removal (from its own toast) un-logs it from history too, so a mis-scan never shows up there.

4.1.0 -- 2026-08-28
--------------------
- Added Category and Freezer filter pills above the inventory list -- tap either to pick from a sheet (with an "All" option) and combine both with each other and with search. The Freezer pill only shows once a second freezer exists. The existing "Browse by category" tile view is unchanged.

4.0.0 -- 2026-08-28
--------------------
- Added support for multiple freezers. The app still ships with just one ("Freezer") by default and nothing changes until a second one is added.
- New "Freezers" page in Settings (below Categories) to add, rename, or remove freezers. Freezer names must be unique, and there must always be at least one.
- Once a second freezer exists, a Freezer field appears on the add-item screen (right after Category) as a tappable pill that opens a picker sheet -- same pattern as Category and the Weight unit. With only one freezer, the field is hidden entirely on Add, since there's nothing to choose.
- The item detail popup always shows the Freezer field: as a plain fixed pill (no picker) with one freezer, or the same tappable pill + sheet once there's more than one.
- The freezer picked most recently in a scanning session is what the next scan defaults to (unlike category, which is learned per barcode) -- you're usually loading one physical freezer at a time, not one per product.
- Deleting a freezer that still has items clears their Freezer field to "not set" (still editable) -- unless the deletion leaves exactly one freezer remaining, in which case those items move there automatically.

3.4.1 -- 2026-08-28
--------------------
- Fixed the Weight field's number input and unit control rendering at different heights (now both a fixed 34px, matching the quantity stepper elsewhere in the app).
- Replaced the plain unit dropdown with a tappable "unit" row that opens a picker sheet of styled chips (grouped Weight/volume vs. Container size) -- the same pattern already used for Category, so it looks like the rest of the app on every platform instead of the browser's native grey dropdown.

3.4.0 -- 2026-08-28
--------------------
- Added a Weight field (a number + a unit dropdown: g / kg / ml / l / oz / lb) to the add-item and item detail screens.
- The unit dropdown also offers "Small container" / "Large container" for homemade items with no real measurement -- picking either hides the number field, since there's nothing to type.
- Weight is learned per barcode, the same as name and category: set it once and future scans of that barcode default to it. Best-effort prefill from OpenFoodFacts' product data on a brand-new barcode, when available.
- Weight is optional and edited the same staged way as the item detail popup's other fields (only applied on Save).

3.3.0 -- 2026-08-28
--------------------
- Added "who added it" attribution: on first open, Freezr asks for your name and tags every item you add with it. Stored per-device (like the theme setting), not synced as household data.
- Shown as "Added by" in the item detail popup only -- not on the main list rows, and it's not used to search or filter.
- Editable anytime via a new "Your name" field in Settings. Changing it relabels items previously added under your old name.

3.2.0 -- 2026-08-27
--------------------
- Reordered the category colour picker into 6 columns (one per hue: red, orange, yellow, green, blue, purple), each running bright to pastel top-to-bottom, plus a bottom row of neutrals (blacks/greys/whites/brown) for categories with no real hue.
- Default category colours updated to match: Fruit and Bread & Bakery now use colours from the grid (they didn't have a clean match before).
- Existing category colours that predate the preset palette (or were left over from the old unordered grid) are now automatically snapped onto the nearest colour in the new grid, so every category is always re-editable from the picker.

3.1.2 -- 2026-08-27
--------------------
- Fixed toast messages (e.g. "That category already exists") being hidden behind an open modal — they now always show on top, so validation errors are actually visible instead of silently doing nothing.


3.1.1 -- 2026-08-27
--------------------
- The category picker (add item, batch review, item detail popup) now shows just the current category as a compact row with a ">" — tap it to pick a different one from a sheet, instead of showing every category's chip on screen at once.

3.1.0 -- 2026-08-27
--------------------
- Category colours now come from a 24-swatch preset palette (bright + pastel, picked via a colour grid) instead of a free-form colour picker, so a colour can always be re-selected later.
- New categories default to a grey preset colour until you pick your own.
- Categories can no longer be added with a name that already exists.
- Categories are now drag-to-reorder in Settings (drag the ☰ handle) — the order set there is the order categories appear everywhere else, including the picker when adding/editing an item.
- Replaced the category dropdown with a friendlier row of coloured, tappable chips when adding, batch-scanning, or editing an item.
- Renamed the "Inventory" tab to "Freezr" with a snowflake icon.
- Renamed "Remove from freezer" to "Remove from Freezr" in the item detail popup.
- The item detail popup's Name field now sits in its own labelled row, matching the Category/Quantity rows.

3.0.0 -- 2026-08-27
--------------------
- Added bottom tab navigation: "Inventory" (the existing scan/list screen) and "Settings" (new), so future settings have a proper home.
- Categories now have a colour, shown as a coloured pill on each list row instead of plain text. Colour is editable per category from Settings.
- Added a "Browse by category" view (▦ button next to search): shows a tile per category with its item count, tap a tile to see just that category's items, with a Back button to return to the full list.
- Added a dark/light/match-device appearance setting (Settings tab), stored per-device. Defaults to dark, same as before.
- Removed the small ✕ delete button from list rows — tap into an item and use "Remove from freezer" instead.
- Removed the barcode number from list rows (still shown in the item detail popup) to reduce clutter now that categories are visible there.

2.0.0 -- 2026-08-27
--------------------
- Added item categories: each item now has a category (Meat, Poultry, Fish & Seafood, Vegetables, Fruit, Bread & Bakery, Ready Meals & Leftovers, Dairy & Ice Cream, Other by default), shown as a tag on each list row and searchable.
- New category is suggested automatically from the product name via built-in keyword matching (no external AI call — keeps the app dependency-free and offline-friendly), same as the item detail popup, before Save.
- The app learns a barcode's category the first time you set it, the same way it already learns item names, so the same product defaults to the same category on future scans (works in single-item add, batch mode, and the item detail popup).
- Added a Categories settings page (⚙️ button next to backup) to rename, add, or delete categories at any time. Renaming or deleting a category updates every item using it (deleted categories fall back to "Other"). Open to everyone for now; could be restricted to an administrator later.

1.2.0 -- 2026-08-27
--------------------
- Added a Backup button (download icon next to search) that exports your full inventory as a JSON file.
- Added Batch scan mode: a toggle (Add stock screen only) that lets you scan a whole stack of barcodes without stopping to name each one, then review and name them all at once afterward via a "Review batch" screen. Validates every item has a name before committing.
- Added an Opened/Sealed toggle to the item detail popup, staged the same way as name and quantity (only applies on Save). Shown as a small "Opened" badge on the list when set. Applies to the oldest unit in a grouped item, since that's the one you'd typically reach for first.
- Cleaned up a harmless duplicate internal function found while working on this batch.

1.1.0 -- 2026-08-27
--------------------
- Fixed the item detail popup so quantity changes are staged just like the name field, instead of applying live: tapping +/- no longer touches the shared list immediately.
- Close/X now discards ALL unsaved changes (name and quantity together) instead of only skipping the name.
- Save now commits name and quantity together in one update and closes the popup, with a single toast summarizing what changed.

1.0.3 -- 2026-08-27
--------------------
- Reverted Enter-to-save on the item detail name field -- quantity can also be adjusted from that popup, so pressing Enter while editing the name no longer risks closing/saving early. Save now only happens when the Save button itself is tapped.

- Renamed "Save name" button to "Save" in the item detail popup.
- Fixed Save not working when pressing Enter/Done on the keyboard while editing a name (was only wired to the button tap).

- Renamed the "Start scanning" button to "Scan items" (in both Add and Remove modes).
